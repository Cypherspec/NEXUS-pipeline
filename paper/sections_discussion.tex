\section{Integration with Mantis}

The pipeline ships as a packaged extension for Mantis, a map interface for
exploring large collections. Installing it modifies nothing: the package goes in
through the application's own Import Extension dialog, which validates the
manifest, states the permissions and the backend actions, and asks for consent.
An earlier version of this work copied three files into the Mantis source and
documented three registrations as diffs; the extension mechanism makes that
unnecessary, and a reader can install the result without a patch.

The package is a sandboxed panel, a worker host, and a Python backend that is
the \texttt{nexus} package itself, vendored beside its entry point. There is no
service to run and no port to configure. Mantis caps a backend invocation at
thirty seconds, so each action bounds its own input and reports what it dropped
rather than truncating in silence.

\paragraph{Results return to the map, not to a table.}
The extension API has no call for colouring points, which turned out to be a
useful constraint. Results are instead expressed in the vocabulary the
application already has: a scaffold family becomes a named bag and is
highlighted, a proposed assay batch becomes the selection, and the Tanimoto
neighbours of a clicked molecule become an edge overlay the panel owns and
releases when it closes. A chemist reading the map sees the answer in the same
terms as everything else on it.

\paragraph{What the integration cost.}
Two failures are worth recording because neither produces an error. The panel's
chart components use utility classes that the host supplies in-tree and an
extension iframe does not, so every class was inert and the layout collapsed
into run-together text; the package now ships the enumerated set those
components reference, and the build fails if one is missing. And inside the dock
the panel iframe paints its background while every element in it measures
$0 \times 0$ --- layout is suppressed for the whole document, \texttt{html}
included. That is not the stylesheet, whose computed height resolves correctly,
and not this package: the application's own reference extension does not render
there either. Installation, permissions, backend dispatch and SDK access are
verified in the running application; the figures above are the same bundle and
the same Python driven through a harness.

\section{Limitations}

\begin{itemize}\itemsep1pt
\item Every implementation here is slower than its established counterpart, often by
      a large factor. Nothing in this work is a performance claim.
\item The aromaticity and valence model is a documented subset, not a complete
      perception engine. Molecules outside it are reported invalid rather than
      guessed at.
\item The generator produces disconnected graphs in the large majority of samples.
      Fragment-validity hides this; strict validity does not, which is why both are
      reported.
\item Binding affinity is evaluated on one kinase panel. Cold-drug generalisation is
      measured, but on a single assay family.
\item Generation hyperparameters were selected on the reported metric with no
      held-out set.
\item Conformal guarantees are marginal. Conditional coverage is measured here
      because the marginal guarantee alone can disguise systematic
      over-confidence on the hardest cases, but no method here guarantees it.
\end{itemize}

\section{Conclusion}

A dependency-free reimplementation is not a contribution in itself, and this paper
does not argue otherwise. What the exercise produced was a set of checks tight enough
to catch three failures that would otherwise have passed silently: a split that
emptied a validation set, a generator beaten by its own control, and an interval that
met its guarantee while carrying no information. Each was found by comparing a number
against something external --- a published table, an untrained baseline, an
analytically known answer --- rather than by reading code. That comparison is cheap,
and it is the part of this work that generalises.
